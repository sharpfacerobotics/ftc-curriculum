# How to Use the Mechanical Track

Telemark started as a programming curriculum. This track covers the other half of the robot: the structure, the mechanisms, the transmission, and the fabrication work that the code eventually drives.

You do not need to have finished the software track to start here, and you do not need to finish this one before writing code. The two tracks describe the same robot from two directions, and a team is strongest when the people on each side understand enough of the other to have a useful argument.

## Who each module is for

| If your role is | Start with |
| --- | --- |
| New member, no assignment yet | Modules 0 through 2 |
| Notebook or documentation lead | Modules 0, 1, and 10 |
| Drivetrain builder | Modules 3, 4, 6, and 7 |
| Mechanism designer | Modules 5, 6, and 8 |
| Electrical lead | Modules 4 and 9 |
| Fabrication or shop lead | Modules 2, 3, 11 |
| Design lead or captain | All of them, in order |

Full role-based sequences with time estimates and checkpoints are in [Mechanical Paths and Time Estimates](/mechanical/learning-paths).

## What is different about this track

The software track gives you a simulator: you write Java, run it, and watch a virtual robot respond. Mechanical work does not simulate that cleanly, so this track uses **calculators** instead. They are small interactive widgets that take the numbers from your design and return the result that decides whether it works.

They are not toys. The gear ratio, arm torque, drivetrain, and wire gauge calculators run the same arithmetic that a mentor would do on a whiteboard before approving a design. Use them while you are designing, not after the part is cut.

:::tip Bring real numbers
Every calculator is only as good as its inputs. Weigh the arm. Measure the actual distance from the pivot to the payload. Read the stall torque off the vendor page for the exact part number you ordered. Estimated inputs produce estimated confidence.
:::

## How to work through a module

1. Read the module overview to see what it covers and why.
2. Work the four lessons in order. Each one ends with fill-in-the-blank practice.
3. Use the calculators with your own robot's numbers, not just the defaults.
4. Take the mastery quiz. It combines conceptual questions with a design review exercise.
5. Write what you learned into your engineering notebook while it is still fresh.

Every official rule, SDK, and vendor source is collected in [Official FTC Documentation](/mechanical/official-docs).

:::info Official references
This track teaches engineering practice. It does not replace the rules. Before any design decision that touches legality, sizing, or the control system, read the current season's official documents.

- FIRST Tech Challenge game manuals: [FIRST Tech Challenge Game and Season Info](https://www.firstinspires.org/resource-library/ftc/game-and-season-info)
- REV control system documentation: [REV DUO Control System](https://docs.revrobotics.com/duo-control)
:::

## A warning about copying

You will see other teams' robots online, and copying a mechanism that clearly works is a legitimate engineering shortcut. What is not legitimate is copying it without understanding it. When the copied mechanism fails at your second tournament, and it will, you need to know why it was built that way in order to fix it.

The purpose of this track is to make sure that when your robot breaks, someone on your team knows what to look at.
