# Lesson 0.1: Blueprints, Houses, Classes, and Objects

A class describes a kind of object. It doesn't represent one specific object that already exists.

Think about a house blueprint. The blueprint states that each house has a street address, a paint color, and a front door. Builders can use the same blueprint more than once. The finished houses share a design, but each house has its own address, color, and door state.

Java uses the same split:

| House example | Java meaning |
|---|---|
| The blueprint | A class definition |
| One completed house | An object created from the class |
| The house's address and paint color | Field values stored by that object |
| Opening one house's door | Calling a method on one object |

The analogy gives you a starting point. The Java code gives you the exact rules.

## From a House to a Robot Arm

`RobotArm` is a class. It states what every arm object stores and what every arm object can do.

Both languages use one class definition to create two independent objects. The syntax differs, but the blueprint-and-house relationship stays the same.

```java
public class RobotArm {
    private String name;
    private double power;

    public RobotArm(String name) {
        this.name = name;
        this.power = 0.0;
    }

    public void move(double requestedPower) {
        power = requestedPower;
    }

    public void stop() {
        power = 0.0;
    }
}
```

This code defines the blueprint. It doesn't create an arm yet.

```java
RobotArm frontArm = new RobotArm("front");
RobotArm rearArm = new RobotArm("rear");
```

These two lines create two objects. Both follow the `RobotArm` class, just as two houses can follow one blueprint. Each arm still stores its own `name` and `power`.

```java
frontArm.move(0.75);
rearArm.move(-0.40);
```

The first call changes only the front arm. The second call changes only the rear arm. Sharing a class does not mean sharing every stored value.

## Why Classes Help a Robot Team

A robot can use one arm in TeleOp and the same arm rules in autonomous. If those rules live in a class, both OpModes can call the same methods. A safety fix then has one home instead of several copied versions.

Classes do not remove every repeated line. They give related state and behavior a clear place to live.

## Terms to Keep

| Term | Meaning |
|---|---|
| Class | A definition that describes fields and methods. |
| Object | One working value created from a class while the program runs. |
| Instance | Another name for an object created from a class. |
| State | The field values currently stored by an object. |
| Method | A named operation defined by a class. |

## Check Your Understanding

```java
RobotArm left = new RobotArm("left");
RobotArm right = new RobotArm("right");
left.move(0.5);
```

<details>
<summary>How many RobotArm objects exist?</summary>

Two. Java creates one object for each `new RobotArm(...)` expression.

</details>

<details>
<summary>Does right's power also become 0.5?</summary>

No. `left.move(0.5)` changes the object referred to by `left`. The other object keeps its own power value.

</details>

<details>
<summary>Which part is the blueprint?</summary>

The `RobotArm` class definition is the blueprint. The values created with `new` are the objects.

</details>
